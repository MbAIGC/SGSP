# 冲突处理闭环设计文档

> 适用于 v0.3.1 重构版(构建产物 `dist/GIT-SYNC-PLUGIN/`)。
> 代码实现见 `src/sync-flow-runtime.js`,注入方式见 `patch/apply-patch.mjs`。

## 1. 目标流程

v0.3.1 把原来「检测到冲突 → 弹一条瞬时提示 → 自动同步继续空转反复报错」的体验,
改造成完整的处理闭环:

```text
发现冲突
   ↓
🔴 冲突状态
   ↓
暂停自动同步(停止定时器)
   ↓
通知用户(顶栏红色闪烁徽标 + 错误通知 + 持久化弹窗)
   ↓
用户选择
   ├── 保留本地版本  → 强制「本地覆盖远端」并提交
   ├── 保留远端版本  → 强制「远端覆盖本地」并提交
   ├── 打开冲突文档  → 尽力定位 _conflict_ 文档(内核搜索),保持暂停
   └── 稍后处理      → 关闭弹窗,继续保持暂停
   ↓
同步成功
   ↓
🟢 恢复自动同步(自动重启定时器,并发出恢复通知)
```

## 2. 同步状态机

| 状态 | 含义 | 触发 | 界面表现 |
|---|---|---|---|
| `idle` | 空闲 | 初始化 / 完成 | 正常图标 |
| `running` | 同步进行中 | 手动/自动发起同步 | 原图标旋转动画 |
| `success` | 同步成功 | 提交成功 | 短暂保持后回 idle |
| `failed` | 同步失败(网络/Token/仓库未初始化) | 非冲突错误 | 保持原 toast 行为 |
| `conflict` | 检测到冲突 | 三方合并返回冲突 | (瞬时) |
| `conflict_paused` | 冲突后暂停自动同步 | conflict 后立即 | 🔴 红色闪烁徽标 + 弹窗 |
| `resolving` | 用户已选择解决方向 | 点击保留本地/远端 | 执行强制覆盖同步 |
| `resolved` | 冲突已解决 | 解决同步成功 | 移除红色徽标,恢复自动同步 |

## 3. 关键行为细则

### 3.1 发现冲突 → 暂停

- 冲突判定:错误链(`cause` 逐层向上,最多 7 层)中出现 `code === 300`(`dr.CONFLICT`,
  即原插件抛出 `Mr(dr.CONFLICT, path, message)` 的错误)。
- 冲突一旦发生立即 `timerTask.removeSelf()`,**自动同步定时器停止**;
  同时记录 `pausedTimer = true`,用于解决成功后恢复。
- 冲突详情(冲突文件路径等)提取后持久化到插件数据文件 `git-sync-flow.json`,
  即使**重启思源**后,再次进入 `conflict_paused` 状态并保持暂停。

### 3.2 暂停期间的行为

- 自动同步定时器已停止,不会再触发同步。
- 若用户手动点击「开始同步」:不会执行同步,而是**重新弹出冲突处理对话框**引导处理。
- 兜底:若定时器在暂停瞬间已有一轮在途执行,该轮会进入状态机被拦截,
  一个暂停会话内只提示一次(避免提示轰炸)。

### 3.3 用户选择与解决

| 选择 | 动作 | 说明 |
|---|---|---|
| 保留本地版本 | `syncDataToCloud(3, true)`(强制本地覆盖远端) | 本地内容提交到远端,冲突文件保留 |
| 保留远端版本 | `syncDataToCloud(2, true)`(强制远端覆盖本地) | 远端内容覆盖本地,冲突文件保留 |
| 打开冲突文档 | 内核搜索 `_conflict_` 文档并尝试打开 | 尽力而为,失败则提示在文件树中查找 |
| 稍后处理 | 仅关闭弹窗 | 状态保持 `conflict_paused`,自动同步保持暂停 |

- 强制覆盖模式(`force = true`)会绕过三方合并,因此解决动作不会二次触发冲突。
- 解决同步成功后:清空冲突详情、移除红色徽标、持久化复位、**自动恢复自动同步**
  (仅当同步模式为「自动」时;手动/完全手动模式不恢复定时器)。

### 3.4 失败处理

- 若解决冲突的同步因网络等原因失败:状态**回到 `conflict_paused`**(不会误判为已解决),
  并重新弹出对话框,等待用户重试。
- 非冲突错误(网络、Token、仓库未初始化等)行为与 v0.3.0 保持一致(原有 toast 与日志)。

## 4. 通知方式

| 场景 | 通知 |
|---|---|
| 冲突发生 | `showMessage`(error)+ 持久化 `Dialog` + 顶栏 🔴 闪烁徽标 |
| 暂停期间自动同步被拦 | 每个暂停会话一次提示 |
| 冲突解决 | `showMessage`「✅ 冲突已处理,自动同步已恢复」 |
| 解决失败 | `showMessage`「❌ 处理冲突的同步失败,冲突仍待处理」+ 重新弹窗 |
| 重启后仍有未解决冲突 | 恢复暂停状态并提示一次 |

顶栏徽标样式(注入在 `index.css`):`.toolbar__item.git-sync-conflict-paused svg`
显示为红色并每秒闪烁一次,鼠标悬停提示「冲突未解决,自动同步已暂停」。

## 5. 设计取舍与已知限制

- **不做跨设备锁**:冲突闭环解决的是「单设备上冲突后的状态与交互」;多设备并发提交
  仍依赖远端 HEAD 校验(原插件的能力范围内),本项目未改动同步算法本身。
- **打开冲突文档为尽力而为**:依赖内核 `/api/search/searchDocs` 搜索结果;
  找不到时引导用户在文件树中打开文件名含 `_conflict_` 的文档。
- **冲突文档是否生成**:沿用原设置「同步冲突时生成冲突文档」;若关闭,
  冲突发生时仍会暂停 + 弹窗(不生成冲突文档)。
- **持久化文件**:`data/storage/petal/GIT-SYNC-PLUGIN/git-sync-flow.json`,
  仅保存状态与最近一次冲突路径,不含任何 Token。
